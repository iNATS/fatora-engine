# Security Policy

Invoices and receipts can contain personal, banking, tax and commercially sensitive information.

- Never attach real documents to public issues or pull requests.
- Do not include document contents in logs.
- Do not use user documents for model training by default.
- Remote model/API providers must be explicitly enabled by the operator.
- Use synthetic fixtures for tests and examples.
- Report vulnerabilities through GitHub's private Security Advisory feature, not public issues.

Until a first stable release and security process are established, treat this project as experimental, not as a certified financial system.
